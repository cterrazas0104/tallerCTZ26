Fase 01 • Arquitectura

Identidad en la Web y Red Edge

01

En la arquitectura web tradicional, publicar un sitio requería alquilar un servidor centralizado (VPS o Hosting compartido), comprar un dominio (.com) y configurar manualmente registros DNS y certificados SSL, lo cual tomaba horas en propagarse. Hoy utilizaremos **Infraestructura Edge (en el borde)**.

Hosting Tradicional

  • • Un solo servidor físico (ej. en Dallas). Si se cae, tu web muere.
  • • Requiere tarjeta de crédito desde el día 1.
  • • Vulnerable a ataques de denegación de servicio (DDoS) directos a la IP.

Arquitectura Edge (Cloudflare Pages)

  • • Tu web se replica en más de 300 centros de datos en todo el mundo (incluido Querétaro y CDMX).
  • • Subdominio profesional gratuito: *.pages.dev
  • • Certificado SSL/TLS (HTTPS) automático e instantáneo.
Nota importante para esta práctica: No ingreses ninguna tarjeta de crédito ni compres un dominio hoy. Todo el flujo que construiremos opera en la capa gratuita empresarial de GitHub y Cloudflare.
Fase 02 • Control de Versiones

Subiendo el Código a la Nube (GitHub)

02

En entornos profesionales, el código nunca se sube por FTP ni se transporta en memorias USB. Se aloja en un repositorio **Git**, lo que permite que cada cambio quede registrado y se despliegue automáticamente.

1

Crear un nuevo repositorio

Inicia sesión en GitHub, haz clic en el botón + (arriba a la derecha) y selecciona New repository. En Repository name escribe exactamente: taller-seguridad

2

Visibilidad Pública y Creación

Asegúrate de que esté marcada la opción Public. Baja hasta el final y haz clic en el botón verde Create repository.

3

Crear el archivo principal index.html

En la pantalla que aparece, busca el enlace azul que dice creating a new file (o el botón Add file -> Create new file). En la caja de nombre del archivo escribe index.html (en minúsculas, todo junto).

4

Pegar el código y hacer Commit

Copia el siguiente bloque de código HTML, pégalo en el editor grande de GitHub y presiona el botón verde Commit changes... (arriba a la derecha) dos veces para confirmar.

// Archivo: index.html (Versión Inicial)
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Mi Web Segura - CESBA</title>
    <style>
        body { font-family: sans-serif; background: #0f172a; color: white; text-align: center; padding-top: 10%; margin: 0; }
        h1 { color: #10b981; font-size: 2.5rem; margin-bottom: 0.5rem; }
        .container { border: 1px solid #334155; padding: 2.5rem; border-radius: 1rem; display: inline-block; background: #1e293b; max-width: 450px; }
    </style>
</head>
<body>
    <div class="container">
        <h1>¡Misión Cumplida! 🚀</h1>
        <p>Infraestructura Edge desplegada exitosamente.</p>
    </div>
</body>
</html>

Cuidado con estos 3 errores frecuentes:

  • 1. Olvidar la extensión: Si nombras el archivo solo index en lugar de index.html, el navegador mostrará texto plano en vez de tu página web.
  • 2. Llamarlo diferente: Los servidores web buscan por defecto un archivo llamado exactamente index.html como portada.
  • 3. No confirmar el Commit: Al dar clic en Commit changes... se abre una ventana emergente; debes volver a dar clic en el botón verde de esa ventana para que se guarde.
Fase 03 • Despliegue Continuo (CI/CD)

Conectando GitHub a Cloudflare Pages

03

Ahora crearemos un **Pipeline CI/CD (Integración y Entrega Continua)**. Conectaremos Cloudflare con tu GitHub para que cada vez que modifiques tu código en GitHub, Cloudflare lo detecte y actualice tu página en todo el mundo en segundos.

1

Ir a Workers & Pages

Entra a tu panel en dash.cloudflare.com. En el menú lateral izquierdo, haz clic en Compute (Workers) o Workers & Pages.

2

Seleccionar la pestaña "Pages"

Si das clic en el botón azul Create, asegúrate de cambiar a la pestaña Pages arriba y elegir la opción Connect to Git (Import an existing Git repository).

3

Autorizar y elegir el repositorio

Conecta tu cuenta de GitHub, selecciona la opción All repositories para evitar bloqueos de permisos, elige tu repositorio taller-seguridad y haz clic en Begin setup.

4

Guardar y Desplegar (Save and Deploy)

Deja las opciones de compilación en blanco (ya que es HTML puro) y haz clic en Save and Deploy. Espera ~30 segundos y Cloudflare te dará tu enlace público terminado en .pages.dev.

Fase 04 • Ciberseguridad Perimetral

Hardening y Firewall de Aplicaciones Web (WAF)

04

Un sitio en internet recibe escaneos de bots automatizados a los pocos minutos de nacer. Vamos a verificar su cifrado en tránsito y cómo configurar reglas de **WAF (Web Application Firewall)** en Capa 7 para filtrar tráfico malicioso antes de que toque nuestro servidor.

1. Verificación SSL/TLS

Haz clic en el icono de ajustes/candado junto a tu URL .pages.dev en el navegador. Notarás que tiene un certificado TLS válido emitido automáticamente.

2. Regla Geográfica WAF

En dominios administrados en Cloudflare (Security -> WAF -> Custom rules), creamos una condición: If Country does not equal Mexico.

3. Managed Challenge

En vez de bloquear a ciegas, aplicamos Managed Challenge: obliga al navegador sospechoso a resolver un reto criptográfico en JavaScript que frena bots y DDoS.

Fase 05 • Backend Serverless + Base de Datos

Cómputo Edge: Cloudflare Workers + KV

05

Una página HTML estática por sí sola no puede guardar datos. En lugar de levantar un servidor tradicional con PHP, Node.js y MySQL, crearemos una función **Serverless (Cloudflare Worker)** conectada a un almacén de datos ultrarrápido **Key-Value (KV)** en el borde.

A Crear la Base de Datos Key-Value (KV)

  1. En el menú izquierdo de Cloudflare, despliega Storage & Databases y haz clic en KV.
  2. Haz clic en el botón azul Create a namespace (o Create).
  3. En Namespace Name escribe en mayúsculas: CONTACTOS y presiona Add.

B Crear el Worker (Tu API Serverless)

  1. En el menú izquierdo, regresa a Workers & Pages y haz clic en el botón azul Create.
  2. En la pestaña Workers, haz clic en Create Worker (o Start with Hello World!).
  3. Puedes dejar el nombre que te sugiere o llamarlo api-contactos y dar clic en Deploy.
  4. Una vez desplegado, haz clic en el botón Edit code (arriba a la derecha).
  5. Borra todo el código que aparece en worker.js, pega el siguiente código y da clic en Deploy (arriba a la derecha):
// Archivo en Cloudflare: worker.js
export default {
  async fetch(request, env) {
    // Si el formulario envía datos por método POST
    if (request.method === "POST") {
      const formData = await request.formData();
      const data = Object.fromEntries(formData);
      
      // Guardar en la Base de Datos KV usando la fecha/hora actual como llave única
      await env.CONTACTOS.put(Date.now().toString(), JSON.stringify(data));
      
      return new Response("¡Guardado en el Edge exitosamente! 🚀", {
        headers: { 
          "Access-Control-Allow-Origin": "*",
          "Content-Type": "text/plain; charset=utf-8"
        }
      });
    }
    return new Response("API Serverless Activa. Envíame un POST desde tu formulario.");
  }
};

C Vincular el Worker con la Base de Datos (KV Binding)

¡PASO CRÍTICO! Si omites este paso, tu Worker no tendrá permiso para escribir en la base de datos y arrojará un Error 1101 / Error 500.
  1. Sal del editor de código regresando al panel de tu Worker (flecha superior izquierda).
  2. Entra a la pestaña Settings de tu Worker y busca la sección Bindings (o Variables and Secrets).
  3. Haz clic en + Add y elige KV Namespace.
  4. En Variable name escribe EXACTAMENTE en mayúsculas: CONTACTOS
  5. En KV namespace selecciona el espacio CONTACTOS que creaste en el inciso A y presiona Deploy / Save.
  6. Copia la URL pública de tu Worker (ejemplo: https://api-contactos.tu-subdominio.workers.dev).

D Conectar tu Página de GitHub con el Worker

Regresa a tu repositorio taller-seguridad en GitHub, entra a index.html, haz clic en el icono del **lápiz (Edit this file)**, reemplaza todo el código por esta versión completa con formulario, **sustituye el atributo `action` con la URL de tu Worker** y haz **Commit changes**:

// Archivo en GitHub: index.html (Versión Final con Formulario conectado al Worker)
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Mi Web Segura - CESBA</title>
    <style>
        body { font-family: sans-serif; background: #0f172a; color: white; text-align: center; padding: 5% 1rem; margin: 0; }
        h1 { color: #10b981; font-size: 2.2rem; margin-bottom: 0.5rem; }
        .container { border: 1px solid #334155; padding: 2rem; border-radius: 1rem; display: inline-block; background: #1e293b; max-width: 420px; width: 100%; box-sizing: border-box; }
        form { display: flex; flex-direction: column; gap: 12px; margin-top: 1.5rem; text-align: left; }
        label { font-size: 0.85rem; color: #94a3b8; font-weight: bold; }
        input { padding: 10px; border-radius: 6px; border: 1px solid #475569; background: #0f172a; color: white; }
        button { margin-top: 8px; padding: 12px; border: none; border-radius: 6px; background: #8b5cf6; color: white; font-weight: bold; cursor: pointer; }
        button:hover { background: #7c3aed; }
    </style>
</head>
<body>
    <div class="container">
        <h1>¡Misión Cumplida! 🚀</h1>
        <p>Infraestructura Edge + Serverless KV.</p>

        <!-- IMPORTANTE: Reemplaza la URL de action por la URL real de tu Worker -->
        <form action="https://TU-WORKER.TU-USUARIO.workers.dev" method="POST">
            <label>Nombre:</label>
            <input type="text" name="nombre" placeholder="Tu nombre completo" required>
            
            <label>Correo:</label>
            <input type="email" name="email" placeholder="alumno@cesba.mx" required>
            
            <button type="submit">Enviar Datos Seguros al Edge</button>
        </form>
    </div>
</body>
</html>

¿Cómo comprobar que todo funciona?

Espera 30 segundos tras hacer Commit en GitHub, recarga tu enlace público .pages.dev, llena tu nombre y correo y presiona Enviar. Verás el mensaje "¡Guardado en el Edge exitosamente!". Luego ve a Cloudflare -> Storage & Databases -> KV -> CONTACTOS -> View y verás tu registro almacenado en formato JSON.

Glosario de Bolsillo (Conceptos que aprendiste hoy)

Edge Computing (Cómputo en el Borde) Ejecutar código y servir páginas desde el servidor físicamente más cercano al usuario (ej. en su misma ciudad), reduciendo la latencia a milisegundos.
CI/CD (Integración y Despliegue Continuo) Automatización que conecta tu repositorio de código (GitHub) con producción (Cloudflare) para publicar cambios automáticamente al hacer Commit.
WAF (Web Application Firewall) Escudo que analiza el tráfico HTTP/HTTPS (Capa 7) para bloquear bots, inyecciones SQL y ataques DDoS antes de que lleguen a tu aplicación.
Serverless + Base de Datos KV Modelo donde programas funciones backend (Workers) y guardas pares Llave-Valor (KV) sin administrar ni pagar servidores encendidos las 24 horas.
